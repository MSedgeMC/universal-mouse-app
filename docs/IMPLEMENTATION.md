# Native architecture

`src/core` contains the captured protocol model, strict JSON/profile validation, versioned private storage, and transaction/readback/rollback logic. `src/drivers` discovers Linux hidraw endpoints and rechecks identity and descriptor on the opened device. `src/platform` integrates desktop controls and the external Input Remapper service. `src/ui/window.cpp` manages the Qt Widgets shell, preset lifecycle and serialized QtConcurrent work queue. `pages.cpp` builds the five device/desktop pages; `design.cpp` supplies shared styling, icons and the macro-event delegate; `viewer.cpp` draws the mouse previews. `src/main.cpp` provides GUI and bounded headless diagnostics.

No browser engine or former helper runtime is used by the native executable. Development oracle scripts run separately. Input Remapper remains external. The initial driver intentionally handles only the captured Instant descriptor; adding a device requires its own reviewed protocol and matching rules.

The original implementation stays in `legacy/resa` to preserve provenance, protocol fixtures, and a migration path. Its only native-port bridge change is a saved-preset JSON export menu. Native hardware backups accept legacy versions 1–4 when their exact allowed fields and identity match.

The native GUI uses C++ geometry and software shading instead of porting the browser WebGL renderer. It provides 2D/3D selection, orbit/zoom, keyboard navigation, auto rotation, event counts, and illustrative lighting. It does not require a GPU context. Optional animation runs only while the relevant preview is visible.

Release 0.3 uses Qt's Fusion widget style with an original black/gray/blue theme, Ubuntu Medium and QPainter icons. The user-selected official GM320 image is cropped and paired with a neutral derivative and lighting alpha mask. Scaled QPixmaps are cached by size and device scale; the color layer updates only when its preview color changes. `tools/gm320-image.py` reproduces the assets on Box from the pinned source hash. The Customize preview has eight mouse/callout hit regions aligned to that image and an on-demand assignment panel. Performance's stage-selection state is separate from the stored active stage. Lighting sliders preserve raw codes and disable unsupported values. Macros use a native numbered event delegate. The optional 3D schematic uses interpolated closed geometry, depth sorting, software shading and separate control faces; it is an illustration rather than a measured GM320 model.

No legacy asset is referenced by the native build or installer. The eighth physical fire button has a display/selection region but no writable protocol field. The redesign does not alter profile version 2, backup addresses, descriptor matching, revision hashing or the backend protocol.
